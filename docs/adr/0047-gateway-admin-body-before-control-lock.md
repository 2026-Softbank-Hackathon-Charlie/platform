# 0047. 관리자 본문을 제한해서 받은 뒤 제어 잠금을 잡는다

- 상태: 채택
- 날짜: 2026-11-07

## 상황

게이트웨이의 `PUT /apps/{app}`는 전역 `controlMu`를 잡고 JSON을 읽었다.
유효 관리자 인증을 가진 클라이언트가 본문을 보내지 않으면 다른 앱의
Hold·Route·Release도 잠금에서 기다렸다. 기존 64KiB 제한은 첫 JSON을 디코드할
때만 검사해 뒤에 붙은 값이나 공백 전체를 제한하지 않았다.

## 결정

관리자 JSON은 기본 10초 안에 전체 64KiB 이하를 받고 한 개의 값으로 검사한다.
`Config.AdminBodyReadTimeout`과 `-admin-body-timeout`으로 수신 시간을 조정한다.
본문 수신과 앱 등록의 순수 검증은 제어 잠금 밖에서 수행한다. 현재 앱 존재와
Hold 검사는 실제 변경과 함께 기존 제어 잠금 안에서 유지한다.

408 `body_timeout`, 413 `body_too_large`, 400 `invalid_request`를 구분하며
유효하지 않은 본문은 제어 상태를 변경하지 않는다. 시간 초과 연결은 닫는다.

## 검토한 대안

관리자 서버 전체에 짧은 WriteTimeout을 주면 정상적인 Hold drain과 Release
dispatch 대기까지 끊을 수 있다. 일반 프록시의 ReadTimeout 변경은 보류·스트리밍
요청까지 바꾸므로 적용하지 않는다. 잠금만 옮기면 느린 본문이 연결을 무기한
점유하므로 JSON 수신 기한도 함께 둔다.

## 결과

느린 등록 요청이 전역 제어 잠금을 점유하지 않으며, 본문을 받는 중 다른 요청이
시작한 Hold도 교체 시 재검사한다. 운영 공격·부하 시험은 별도이며 이번 변경에
운영 요청이나 설정 변경은 포함하지 않는다. 재현·회귀는 실제 로컬 HTTP 서버를
사용하는 테스트이고, cloud migration 성공을 증명하지 않는다.
