# 0051. 온프레미스 연결은 장비 전용 서비스와 서버 실측으로 완료한다

- 상태: 채택
- 날짜: 2026-11-07

## 상황

ADR 0049의 코드 발급·인증 뒤 신규 장비의 등록 작업자가 없었다. 설치 프로그램은 k3s를 선택 설치한 뒤 종료했으며, 사용자는 명령 한 번으로 실제 플랫폼 연결이 완료된다고 기대했다. 기존 Hello World의 수동 등록 성공은 신규 PC의 자동 등록을 검증하지 않는다.

## 결정

일회용 코드 인증으로 등록에만 쓰는 연결 세션을 발급한다. 클라이언트가 관리 평면으로 전달하는 클러스터 자격증명은 장비 내부의 제한된 서비스 계정이 발급하는 단기 TokenRequest 두 개이며, 관리자 kubeconfig는 전송하지 않는다. 연결 서비스가 주기적으로 갱신한다. 세션 해시, 장비 UID, 환경 소유권, 작업 lease 및 실측 검사를 PostgreSQL에 보관한다. 복구에 필요한 접속 정보는 기존 비밀 암호화 키와 등록 ID로 암호화한다.

전용 OAuth·tag·고정 장비 hostname을 사용하는 Tailscale 경로를 재사용한다. 임의 API URL, 실행 명령, 업로드된 manifest는 받지 않는다. 장비 소유권 확인 후 Kubernetes CA와 hostname을 검증하고 실제 kube-system UID를 확인한다. 기존 환경을 교체하지 않으며 다른 등록·장비의 갱신은 거부한다.

관리 평면은 등록별 API 경로와 Argo cluster Secret·AppProject·ApplicationSet을 소유권 및 resourceVersion을 검사하며 생성한다. 새 환경은 동적 registry에 반영되고, 재시작 시 암호화된 상태에서 복구한다. 새 앱 namespace에는 Pod Security restricted를 강제한다. 로컬 admission 설치가 실패하면 연결 서비스를 시작하지 않는다.

서버가 Kubernetes/Ready node, 네트워크·TLS·UID, 배포 권한과 protected namespace admission 거부, 실제 이미지 및 테스트 Pod UID가 포함된 HTTP 응답을 관측한다. 다섯 검사와 Argo·registry 등록이 모두 성공한 경우에만 ready를 저장한다. 실패·폐기와 등록 경합은 lease/version CAS로 처리하고, 폐기 시 소유한 외부 접속 자격을 회수한다. 앱과 DB는 연결 폐기로 자동 삭제하지 않는다.

## 검토한 대안

- 관리자 kubeconfig를 브라우저로 업로드: 장기 관리자 자격과 환경 교체 권한을 과도하게 노출하므로 제외했다.
- 짧은 토큰 한 번 발급 후 설치 프로그램 종료: 만료 후 연결이 끊겨 제외했다.
- 새 역방향 프록시 프로토콜: 기존 Tailscale·Argo 구조보다 변경과 운영 범위가 커 제외했다.
- 클라이언트가 ready 결과를 보고: 실제 관리 평면의 접근 가능성과 배포 권한을 증명하지 못해 제외했다.

## 결과

이 결정은 사용자 요청에 따른 구현 방향이다. 채택 상태가 운영 OAuth 발급이나 권한 변경 승인, 배포 성공을 뜻하지 않는다. 전용 OAuth·관리 평면 권한·API 이미지의 연결 바이너리·프로파일이 없으면 코드 발급부터 거절한다.

기본 연결 검사는 신규 k3s 연결과 제한된 테스트 배포를 증명한다. CNPG·Sealed Secrets·MinIO·GPU 등의 설치나 이전 동등성을 증명하지 않으며 기존 capability 거절을 유지한다. 이름 예약 뒤 실패한 등록은 다른 장비가 자동 재사용하지 못한다. 명시적 운영자 정리가 필요하다. 영속 권한 설정, 실제 클러스터 통합 시험 및 독립 검토 결과를 배포 전에 확인한다.
