# 0036. 이전 부하 예산은 엔진 SDK의 운영자 정책을 사용한다

- 상태: 채택
- 날짜: 2026-11-07

## 상황

플랫폼이 고정한 이전 엔진 버전에는 운영 DB 부하 승인과 배치 검증 예산이 없었다. 엔진 저장소만 변경하면 플랫폼 실행에는 적용되지 않는다.

## 결정

부하 예산 기능을 포함한 SDK 커밋으로 go.mod/go.sum을 갱신한다. 기존 `EngineFactory`의 `engine.New`가 서버의 `HOPMIGRATE_LOAD_POLICY`를 읽게 하고 별도 클라이언트 설정 API를 만들지 않는다. 정책의 양쪽 endpoint 등록과 지표 신선도 검사는 엔진이 소유한다. 기존 metric 이벤트와 단계 증거를 그대로 전달한다.

## 검토한 대안

- 플랫폼에서 별도 부하 상태 머신 구현: CLI와 서버의 동작이 달라지고 promotion 안전 경계를 중복 관리한다.
- 클라이언트 Plan에서 Prometheus 및 임계값 지정: 비신뢰 클라이언트가 보호 정책과 서버 HTTP 대상을 바꿀 수 있어 제외한다.
- SDK 갱신 없이 문서만 추가: 플랫폼에서 기능이 실행되지 않아 제외한다.

## 결과

기존 API 계약과 실행 경로를 유지한다. 정책 미설정 시 가드는 꺼져 있다. 새 SDK의 기존 병합된 검증/rollback 안전 수정도 포함하므로 플랫폼 전체 검사를 수행한다. 실제 운영 배포와 부하 절감 측정은 별도이며, 실행 중 물리 복제 속도 상한은 제공하지 않는다. 설정은 [운영 안내](../db-load-budget.md)를 따른다.
