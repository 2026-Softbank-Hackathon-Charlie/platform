# 0052. 쓰기 기록의 마지막 커밋 시각과 수집기 활동 시각을 구분한다

- 상태: 채택
- 날짜: 2026-11-08

## 상황

`moimroom-mig-gke-to-onprem-20261107-141917`은 이전 검증을 통과했지만
Plan에 `verify.writtenRecords`가 없어 쓰기 누락은 `not_configured`였다.
조회된 스트림에는 실제 커밋 기록 132개가 있었고 마지막 커밋 시각은
13:42:12 UTC로, 실행 시작 14:19:17 UTC보다 약 37분 전이었다.
자동 연결은 마지막 **커밋**이 10분 이내인 경우에만 가능했다.

앱의 reporter는 기존 outbox를 반복 조회하고 같은 기록을 재전송한다.
서버는 중복을 정상 수락하되 기존 기록의 시각은 바꾸지 않는다. 따라서
살아 있는 수집기와 한동안 쓰기가 없는 앱을 구분할 수 없었다.
이 코드 경로는 시간 조건에서 연결을 생략한다. 당시 수집기가 실제로
살아 있었는지는 기존 통계만으로 확인할 수 없다.

## 결정

검증된 전용 수집기 토큰으로 수락한 비어 있지 않은 커밋 배치의 서버 수신 시각을
별도 `written_record_collectors` 행으로 저장한다. 중복 배치도 활동으로 인정하되
기존 이벤트·커밋 시각·최초 수신 시각과 기록 수는 그대로 둔다. 배치와 활동 갱신은
같은 트랜잭션에 두어 실패한 요청은 활동을 남기지 않는다.

`lastReceivedAt`은 이 활동의 관측 시각이다. 일반 agent나 client acknowledgement,
빈 배치, 세대·내용 충돌 요청은 수집기 활동 증거가 아니다. 이전 기록으로 활동을
소급 생성하지 않는다. `latestAt`은 계속 마지막 커밋 시각을 뜻한다.

자동 연결은 비어 있지 않은 `application_commits / reservation_inserts` 스트림,
10분 이내의 실제 수집 활동, 원본·대상 DB와 일치하는 generation을 요구한다.
원본·대상 identity를 읽지 못하면 연결하지 않고 원인을 서버 로그에 남긴다.

## 검토한 대안

- 10분 제한만 제거: 멈춘 수집기나 오래된 데이터를 연결할 수 있어 제외했다.
- 마지막 커밋 시각을 수신 시각으로 덮어쓰기: 감사 기록의 의미를 바꾸므로 제외했다.
- 새 앱 heartbeat API 추가: 기존의 주기적 재전송으로 관측할 수 있어 이번 수정에는 불필요하다.

## 결과

조용한 앱도 검증된 수집기가 활동하고 세대가 일치하면 이후 새 Plan에 기록을
자동 연결할 수 있다. 기록이 없는 앱과 오래된 데이터의 검증을 0건 성공으로 만들지 않는다.
기존 실행·Plan·검증 결과는 변경하지 않으며 과거 미측정을 0으로 바꾸지 않는다.
검증 범위는 수집한 예약 INSERT의 PK 존재 여부이며 모든 종류의 쓰기나 IAM 동등성을 증명하지 않는다.

마이그레이션 0019는 별도 온프렘 등록 PR의 0018 번호와 충돌하지 않도록 선택했다.
기존 migration loader는 파일 이름별로 추적하므로 0018 스키마에 의존하지 않는다.
