# 0046. 승인 전에 Plan의 쓰기 기록 연결 여부를 표시한다

- 상태: 채택
- 날짜: 2026-11-07

## 상황

2026-11-07 18:08:00 KST에 종료된 `moimroom-mig-gke-to-eks-20261107-090542`는
이전 자체는 성공했지만 `result.writeVerification.status=not_configured`,
`reason=written_records_not_configured`였다. verify report에 `written`도 없었다.
480건의 HTTP 요청과 실패 0건은 대상 DB에서 성공한 쓰기의 PK를 대조한 증거가 아니다.
따라서 쓰기 누락의 미측정 표시는 정확하며 과거 결과를 0으로 바꾸면 안 된다.

조사 시점의 `app-moimroom-mig` 중앙 기록은 count 0이었다. EKS/GKE 앱 배포에
`WRITTEN_RECORDS_*` 명시 설정이 없고, 앱 시크릿의 이름 목록에도 `HOST_CODE`만
있었다. 앱의 수집기 코드는 존재하지만 설정 없이 비활성이다. 또한 현재 infra의
설정 초기화 경로는 `PLATFORM_WRITTEN_RECORD_TOKENS`를 전달하지 않는다.
이 문서는 현재 설정과 저장된 실행의 증거를 구분하며, 과거 환경변수의 값을
조회하거나 당시 수집 트래픽 전체를 복원한 것은 아니다.

Plan 요약에는 쓰기 기록 연결 여부가 없어 운영자는 승인 전에 이 제한을 볼 수 없었다.

## 결정

`PlanSummary.writtenRecordsConfigured`를 optional boolean으로 추가한다.
새 Plan은 실제 `verify.writtenRecords`의 비어 있지 않음으로 true/false를 계산한다.
스트림과 상대 파일 경로를 모두 포함하되 경로나 자격정보는 요약에 노출하지 않는다.
true는 설정만 의미하며 수집 성공·입력 완전성·검증 완료를 의미하지 않는다.
구버전 서버와 저장된 과거 요약에서 필드가 없으면 unknown으로 유지한다.

콘솔은 승인 및 승인 후 재시작 전에 이 상태를 표시한다. false이면 그대로
시작할 때 쓰기 누락이 미측정으로 남는다고 알리고, 수집을 활성화해 기록을
받은 뒤 새 Plan을 만들도록 안내한다. 기존 Plan은 자동으로 변경하지 않는다.
기존 선택적 쓰기 검증 계약과 승인 권한은 유지하며 새 필수 차단 조건을 만들지 않는다.

## 검토한 대안

- 미측정을 0으로 표시: 대상 PK 대조가 없어 배제했다.
- 현재 스트림 통계로 과거 실행을 보정: 당시 동결 입력과 다른 증거여서 배제했다.
- 모든 이전을 수집기 설정 전까지 차단: 현재 optional 검증 계약을 바꾸므로 이 수정에서 하지 않는다.
- Plan 원문을 브라우저에서 파싱: 원문·새 조회 권한이 필요해 비밀 없는 서버 요약을 사용한다.

## 결과

승인 전에 미측정 예상 여부를 확인할 수 있다. 실제 측정을 켜려면 운영자가
ADR 0041의 전용 append token을 플랫폼에 설정하고, 앱의 URL·stream·token을
기존 앱 시크릿 경로로 넣어 재배포해야 한다. source의 identity/outbox가 존재하고
target에도 WAL로 전달됐는지, 중앙 count가 증가하는지 확인한 뒤 새 Plan이
해당 stream을 연결하는지 확인한다. DB generation 불일치나 10분 freshness 조건을
완화하지 않는다. 실행 중인 이전이 있으면 API·앱을 재시작하지 않는다.

이번 변경은 운영 토큰 발급·시크릿 변경·재배포·실제 이전을 수행하지 않는다.
과거 실행과 현재 수집기 상태를 연결한 진단은 사라진 과거 쓰기를 소급 측정하지 못한다.
