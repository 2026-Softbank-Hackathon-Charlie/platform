# 0008. AI 에이전트의 도구 호출은 플랫폼이 세션 단위로 받아 실시간으로 내보낸다

- 상태: 채택
- 날짜: 2026-11-02

## 상황

본선 규칙은 에이전트의 tool 호출과 결과가 로그와 UI에 실시간으로 보이고, 모든 행동이 감사 로그에 남아야 한다고 요구한다. 에이전트 코드는 D 영역(ai-sandbox)이 만들고, 화면은 콘솔이 만든다. 둘 사이에 기록을 받고 내보내는 곳이 필요했다.

## 결정

- 에이전트는 agent 토큰으로 세션을 열고(`POST /v1/agent/sessions`), 도구 호출과 결과, 막힌 명령, 판단을 이벤트로 보낸 뒤(`.../events`), 끝을 알린다(`.../finish`).
- 콘솔과 CLI는 이전 run과 같은 SSE 규칙으로 받는다. 처음 snapshot, 저장된 이벤트, 실시간 이벤트, 끝날 때 snapshot 순서이고, Last-Event-ID로 다시 접속하면 빠진 이벤트를 받는다.
- 세션은 만든 에이전트와 operator만 이어서 쓸 수 있다. 이벤트의 입력과 출력은 64KiB까지 받고, 세션 하나에 이벤트는 5000개까지 받는다(넘으면 409 `session_full`).
- 비밀값은 저장하기 전에 가린다. password, secret, token, authorization, api key 같은 키 아래의 문자열을 가리고, 문자열 안의 `NAME=value`, DSN의 비밀번호, Bearer 토큰, AWS 액세스 키 id, PEM 개인 키도 가린다. `${VAR}` 참조와 토큰 수 같은 숫자는 남긴다.
- NUL 문자와 잘못된 UTF-8은 저장하기 전에 정리한다. PostgreSQL이 받지 못해서 500이 나기 때문이다.
- 세션은 Plan이나 run과 연결할 수 있어서, 승인 화면에서 그 Plan을 만든 AI의 행동을 같이 보여 줄 수 있다.

## 검토한 대안

- 에이전트가 자기 로그를 파일로 남기고 콘솔이 읽는 방식: 실시간으로 보여 주기 어렵고, 에이전트가 기록을 지우거나 고칠 수 있다.
- 감사 로그 하나에 모두 넣는 방식: 감사 로그는 사람과 토큰의 요청 기록이다. 도구 호출의 입력과 출력까지 넣으면 양과 형식이 맞지 않는다.

## 결과

- 에이전트가 끝을 알리지 않고 죽어도 세션이 계속 열려 있지 않도록, 이벤트 없이 `PLATFORM_AGENT_IDLE`(기본 30분)이 지난 세션은 플랫폼이 `cancelled`로 닫는다. 보고 있던 스트림은 마지막 snapshot을 받고 닫힌다.
- 이벤트 목록은 한 번에 500개씩(최대 2000개) 돌려주고 `nextAfter`로 이어 받는다. SSE 재생도 500개씩 나눠 보낸다.
- 플랫폼은 기록을 받는 쪽일 뿐, 에이전트가 무엇을 할 수 있는지는 D 영역의 도구 허용 목록과 샌드박스 권한이 정한다.
