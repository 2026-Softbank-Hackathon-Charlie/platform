# 0063. 이전 판단의 핵심 근거만 AI가 선택하고 공개 가격은 참고 출처로 분리한다

- 상태: 채택
- 날짜: 2026-11-08

## 상황

추천 캐시에서 docker-doom GKE→EKS는 총비용·용량·데이터 정책이 미확인인데, AI가 일반 비용 확인 문구와 m7i.large 참고 가격만 골랐다. 기존 후보가 준비 상태, 체크리스트, 시장 참고 가격을 같은 이유 목록에 넣고 미확인 후보에도 `stay`를 허용했기 때문이다. 참고 VM이 실제 앱의 인스턴스라는 근거는 없다.

## 결정

후보마다 원본·대상, 앱의 미확인 조건, 같은 앱·운영시간의 입력 총비용을 먼저 평가해 핵심 이유 하나를 만든다. 진행 중인 이전, 데이터 보관 정책 제한, 준비 상태 미확인, 비교 견적 미확인은 `insufficient`만 허용한다. 완전한 비교에서 대상 비용이 낮으면 `move|insufficient`, 현재 비용이 낮거나 같으면 `stay|insufficient`를 허용한다. AI는 허용 후보의 우선순위를 선택하고 충분한 근거가 있어도 판단을 보류할 수 있다. 현재·대상 견적은 운영자 입력이며 실측 청구액이나 실제 이전의 안전성 증명이 아니다.

후보의 `reasons`를 핵심 이유 하나로 제한하므로 기존 원문 1~2개 선택 검증을 통과하면 실제 판단 근거가 반드시 포함된다. 공개 가격과 시장 전망은 `sources` 안에서만 전달한다. AWS 참고 출처 제목에 지역·OS·인스턴스 예시·시간당 단가·컴퓨트 한정·실제 앱 인스턴스 미확인을 명시한다.

새 JSON 필드·CLI·권한 변경 없이 기존 strict AI 입력을 유지한다. nonce·후보 ID·허용 동작·원문 이유 검증, 캐시 15분, 읽기 전용 상태 확인과 단일 Job 생성은 유지한다. 실제 이전은 준비 검증·계획·승인을 다시 거친다.

## 검토한 대안

- 프론트에서 가격만 보고 앱의 이익을 추정: 앱별 비용·용량·정책 근거가 없어 제외했다.
- AI 프롬프트에만 주요 이유 선택을 요청: 서버가 일반 참고 가격만 받아도 통과하므로 제외했다.
- 필수 주이유를 새 필드로 추가: 기존 CLI의 strict JSON 소비자와 배포 순서 변경이 필요해 기존 필드 안에서 해결했다.

## 결과

새 후보는 참고 가격만 이유로 선택하거나 미확인 상태를 유지 권고로 오해할 수 없다. API와 UI의 과거 캐시는 만료 전까지 기존 이유를 포함할 수 있어 UI는 미확인 필드에 따른 판단 보류를 먼저 표시한다. 비용 파일이나 실제 자원·정책 확인이 없으면 이전 이익을 새로 만들지 않는다. 운영 AI의 새 결과와 배포 확인은 코드·fixture 검사와 별개로 기록한다.
