# 0006. Plan이 참조하는 파일은 플랫폼이 받아서 실행할 때 붙인다

- 상태: 채택
- 날짜: 2026-11-02

## 상황

엔진 Plan은 대상 CNPG 매니페스트(`target.manifest`)와 부하 생성기의 성공 기록(`verify.writtenRecords`)을 실행하는 컴퓨터의 파일 경로로 받는다. 엔진을 노트북에서 직접 돌릴 때는 문제가 없지만, 플랫폼 API 뒤에서는 이 파일을 서버에 올릴 방법이 없었다. 그리고 경로마다 Plan JSON을 손으로 써야 해서 6개 경로를 준비하기 어려웠고, 성공한 이전을 되돌리려면 반대 방향 Plan을 다시 써야 했다.

## 결정

- 매니페스트는 Plan 첨부로 받는다. 승인 전에만 `PUT /v1/plans/{ref}/attachments/{name}`으로 올릴 수 있고, Plan에서는 `attachment:<name>`으로 가리킨다. 실행할 때 플랫폼이 상태 디렉터리에 파일로 풀고 경로를 바꿔 넣는다.
- 사람이 본 내용 그대로 실행되도록 Plan에 `revision`을 둔다. 제출하면 1이고 첨부를 올릴 때마다 1씩 오른다. 승인 요청은 검토한 revision을 함께 보내야 하고, 그사이 첨부가 바뀌었으면 409로 거부한다. 확인과 승인은 하나의 조건부 쓰기로 처리한다.
- 성공 기록은 스트림으로 받는다. 부하 생성기가 `POST /v1/written-records/{stream}`으로 몇 초마다 묶어서 보내고, Plan에서는 `stream:<name>`으로 가리킨다. 플랫폼은 단계를 하나씩 부르므로, verify 단계 직전에 그 스트림의 기록을 파일로 써서 엔진에 넘긴다.
- 앱과 환경별 DB, 버킷 정보를 `PLATFORM_APPS_FILE`에 두고, `POST /v1/plans/draft`가 이것으로 Plan 초안을 만든다. AI 플래너도 이 초안에서 출발할 수 있다.
- `POST /v1/migrations/{runId}/rollback`은 성공한 run의 원래 Plan에서 원본과 대상을 바꾼 Plan을 만들어 바로 실행한다. operator만 부를 수 있고, 그 호출을 사람의 승인으로 기록한다. 엔진의 finalize가 옛 원본을 새 primary의 복제본으로 남기므로, 반대 방향 이전이 같은 엔진 경로로 동작한다.
- Plan의 DSN과 게이트웨이 설정에는 엔진이 환경 변수를 확장한다. 그래서 플랫폼은 확장 전에 JSON을 디코드한 값으로 검사한다. `${VAR}`는 DSN의 비밀번호 자리 전체로만 쓸 수 있고, 변수 이름은 `_PGPASSWORD`로 끝나야 한다. 앱 설정에 적은 비밀번호 변수는 그 앱의 DB 호스트와 포트로 가는 DSN에서만 쓸 수 있다. 오류 메시지와 저장하는 DB 호스트는 확장하기 전의 값에서 만든다.

## 검토한 대안

- 원본 JSON 바이트에서 `${`를 찾는 방식: JSON 유니코드 이스케이프로 `$`를 쓰면 검사를 지나 엔진에서 확장된다. 실제로 이 방법으로 서버 환경 변수를 꺼낼 수 있었다. 엔진과 같은 방식으로 디코드한 값을 검사해야 한다.
- 매니페스트를 Plan JSON 안에 넣는 방식: 엔진 Plan은 알 수 없는 필드를 거부한다. 엔진의 공개 계약을 바꾸지 않으려고 첨부로 분리했다.
- 성공 기록을 이전이 끝난 뒤 파일 하나로 올리는 방식: verify는 전환 직후에 돈다. 그때까지의 기록이 이미 서버에 있어야 하므로 계속 보내는 스트림이 맞다.
- 되돌리기를 별도 엔진 기능으로 만드는 방식: 이미 검증된 이전 경로를 그대로 쓰는 편이 새 코드를 만드는 것보다 안전하다.

## 결과

- 스트림 이름은 데모를 할 때마다 새로 정하는 것이 좋다. 지난 데모의 기록이 남아 있으면 그 사이 DB를 초기화했을 때 누락으로 보인다.
- 기록 수신 요청은 감사 로그에 남기지 않는다(거부된 요청은 남긴다). 몇 초마다 오는 데이터라 감사 대상이 아니다.
- 되돌리기는 성공한 run에만, 한 번만 할 수 있다. Plan의 `rollback_of`에 유일 인덱스를 걸어 동시 요청도 막는다.
- key=value 형식의 DSN과 Plan에 직접 적은 `gateway.token`은 받지 않는다. 비밀번호는 DSN에 그대로 들어가므로 URL에 쓸 수 있는 문자여야 한다.
