# 0013. 레지던시 정책은 새 run을 시작하기 전에 원본 전체 인벤토리로 검사한다

- 상태: 채택
- 날짜: 2026-11-03
- 관련: [0011 Preflight 코어](0011-preflight-core.md)

## Context

0011에서 레지던시 판정 코어를 만들었지만 어느 실행 경로에도 연결하지 않았다. 그래서 `kr-only` 데이터가 든 클러스터도 다른 나라 환경으로 그대로 물리 복제될 수 있었다.

엔진은 CNPG 물리 복제를 쓴다. 대상은 원본 클러스터 전체를 복사하므로 판정 단위도 클러스터여야 한다. 이때 클러스터 안의 모든 database·schema·table을 실제로 알아야 판정할 수 있다.

## Decision

1. **게이트 위치는 `plans.Service.Reserve`다.** 수동 시작과 롤백(수동·자동)이 모두 여기를 지난다. Reserve는 엔진이 target manifest를 적용하기(최초 replica 생성) 전에 실행되므로, 데이터 이동이 시작되기 전에 막을 수 있다. 거부하면 Plan을 `approved`로 되돌리고 409 `residency_denied`를 반환한다.
2. **인벤토리는 서버가 직접 수집한다(`preflight/inventory`).** 확장된 `source.dsn`으로 접속해 `pg_database`의 모든 DB에 차례로 접속한다. 각 DB에서 `pg_class`의 테이블·파티션·구체화 뷰를 나열한다. 세션은 읽기 전용이고 statement timeout을 걸며, 행 데이터는 읽지 않는다. 다음 경우에는 불완전으로 판정해 거부한다.
   - 접속할 수 없는 DB가 있음
   - 대용량 객체(large object)가 있음
   - 지원하지 않는 식별자가 있음
   - 수집 시간이 30초를 넘김
   - 테이블이 하나도 없음
3. **정책은 `PLATFORM_RESIDENCY_POLICY_FILE`로 켠다(opt-in).**
   - 파일이 잘못됐거나, 정책이 `PLATFORM_ENVS_FILE`에 없는 환경을 쓰면 서버를 시작하지 않는다.
   - 설정하지 않으면 지금 동작 그대로 두고 경고만 남긴다.
4. **롤백 Plan은 면제한다.** 대상은 서버가 `Rollback`으로 만든 Plan, 즉 `rollbackOf`가 있는 Plan뿐이며, 사용자가 제출한 Plan에는 이 필드를 넣을 수 없다. 롤백은 데이터를 원래 출발한 환경으로 되돌리는 작업이다. 검사 실패 때문에 장애 환경에서 빠져나오지 못하는 쪽이 더 위험하다고 봤다. 면제한 사실은 감사 로그에 `residency: rollback_exempt`로 남긴다.
5. **`files`(버킷 복사)는 정책 파일의 `buckets` 등록으로 검사한다.** 가장 단순한 방식을 택했다.
   - 버킷마다 저장된 환경(그 환경의 국가)과 분류(버킷 전체를 하나의 단위로)를 운영자가 적는다. 클라우드 API로 실제 리전을 조회하지는 않는다.
   - 원본 버킷의 분류가 대상 버킷 국가를 허용하지 않으면 `bucket_country_not_allowed`로 거부한다.
   - 원본이나 대상 버킷이 등록돼 있지 않으면 `unregistered_bucket`으로 거부한다.
   - DB 판정과는 독립이라 둘 중 하나라도 위반하면 전체를 거부한다.
6. **재개(resume)는 검사하지 않는다.** 이미 데이터가 이동 중인 run이고, fence나 승격 도중에 멈추면 복구가 위험해진다.
7. **결과와 감사 기록에는 고정 사유 코드, 검증된 `db.schema.table`, policy digest만 남긴다.** DSN, 호스트, SQL·SDK 오류 원문은 남기지 않는다.

## Alternatives

| 대안 | 판단 |
|---|---|
| 승인 시점에 검사 | 승인과 시작 사이에 테이블이 생기거나 바뀔 수 있다. 시작 직전 검사가 더 신선하다. 승인 화면 미리보기는 후속 작업 |
| 인벤토리를 Plan이나 에이전트가 제출 | 요청자가 목록을 조작할 수 있다. 기각 |
| `verify.tables`만 검사 | 복제 범위가 아니라 비교 범위일 뿐이다. 기각 |
| 롤백도 동일하게 검사 | 수집 실패나 정책 변경으로 장애 복구가 막힌다. 사용자 결정으로 기각 |
| 게이트를 항상 켬 | 정책 파일이 없는 기존 배포와 데모가 모두 막힌다. opt-in으로 결정 |

## Consequences

- 정책을 켠 서버에서는 "정책 위반 시 이전 차단"이 실제 시작 경로에 적용된다.
- **신뢰 가정**: `source.dsn`이 Plan의 CNPG 클러스터 rw 서비스를 가리킨다고 가정한다. 엔진과 fence gate도 같은 가정을 쓴다. 승인자는 요약의 `dbHost`를 확인해야 하고, `PLATFORM_DSN_HOST_SUFFIXES`로 접속 가능한 호스트를 제한한다.
- **수집 권한**: 수집 계정은 모든 DB에 CONNECT할 수 있어야 한다. 기본 PUBLIC 권한이면 충분하다. 권한이 없으면 fail-closed로 거부된다.
- **잠금 시간**: 수집은 `startMu`를 잡은 채 최대 30초 걸릴 수 있다. 그동안 다른 시작 요청은 기다린다.
- **한계**
  - 시작 전에 이미 존재하던 replica에는 데이터가 이동했을 수 있다.
  - 버킷 위치는 운영자가 선언한 값이다. 실제 버킷이 다른 리전에 있거나 GCS 멀티리전이면 잡지 못한다. 버킷 안의 경로별 분류도 지원하지 않는다.
  - catalog와 수집기가 함께 놓친 데이터는 찾을 수 없다.
  - unlogged 테이블처럼 실제로는 복제되지 않는 테이블도 목록에 나온다. 더 엄격한 쪽으로 판정한다.
- **후속 작업**
  - 승인 화면에서 판정 미리보기
  - 판정 결과 저장(Plan digest + TTL)
  - 클라우드 API로 버킷 실제 리전 대조
  - parity 연결
